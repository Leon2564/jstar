## 一、原则（来自《JSTAR 关键产品决策》）

- 尺度：写真级，性感不露骨。所有提示词都过自动检查（`tools/media/tests`：不得出现 nude / lingerie / bikini 等）。
- 艺人本人**只从她在 Seedance 私有真人资产库里核验过的资产生成**（第五节）。文字描述画不出真人，只会编出一张脸再挂上她的名字；本地照片会被平台拒收。所以人物镜头在资产到位前一律跳过。
- 构图：一律看镜头、第一人称；藏青底加玫瑰粉光。人物脸部用明亮柔和的主光、写真集程度的自然修饰（v1 的「不修图、可见毛孔、暗光」让人显老，已弃用）。
- 线上尺度＝穿着得体的陪伴（日常、约会、居家、正装）；不出现内衣、泳装、露肩吊带、校服。
- 场景、服装、道具镜头**不出现人**（提示词强制写明，测试校验）。
- 需要循环的镜头一律**机位锁定**，只有空气、光、窗帘在动，这样才能做成无缝循环。提示词里不写任何器材词（「tripod」曾让 nana-day 画面里出现一台三脚架相机）。
- 循环接缝：人物循环用同一张关键帧做首帧和尾帧（Seedance first_frame + last_frame），不靠交叉淡化；其余循环在最相似的两帧处剪开，交叉淡化 ≤ 0.3 秒（v1 的 1 秒淡化造成「笑容融化」、双眼重影和围巾重影）。

## 四、怎么用

```bash
npm run media:gen -- --dry                      # 列出镜头表，不花钱
npm run media:gen -- --category scene           # 按类别生成（scene / costume / prop / ambient / character）
npm run media:gen -- --only mahiro-night-16x9   # 指定镜头
npm run media:gen -- --only eimi-night-9x16 --redo   # 已完成的镜头换种子重拍（如机位漂移导致循环跳帧）
npm run media:process                           # 后期：无缝循环、网页编码、海报图、多视图，并更新 apps/web/src/data/media.gen.ts
```

- 密钥放在仓库根目录的 `.env.seedance`（已 gitignore），不进代码、不进日志。
- 生成可断点续跑：`tools/media/out/state.json` 记录每个镜头的任务 ID、种子和提示词指纹。重跑时已完成的跳过，进行中的继续轮询，提示词改了才重新生成。
- 下载：新加坡对象存储单连接只有约 15 KB/s，所以按字节区间 16 路并发下载。
- 后期产物（`apps/web/public/media/<镜头>/`）：AV1 全尺寸（桌面优先；人物 CRF 32，其余 38），H.264 全尺寸与 2/3 尺寸（手机只下小的），海报图全尺寸（1280）与半尺寸，16:9 另出 1920 宽海报（`poster-1920.jpg`），环绕镜头只出 8 张视图和一张拼图（网页不播这些视频）。
- `media:process -- --only <id>` 只重做指定镜头，其余镜头按磁盘上已发布的文件写回索引（不重编码）。
- 花费：每个 Seedance 任务的 token 数写入 `tools/media/out/spend.jsonl`（按官方牌价 $10.70／百万 token 估算），OpenRouter 的关键帧与评分也记在同一文件，汇总进 `docs/SPEND.md`。
- 1080p 一段 7 秒循环：AV1 约 0.3 MB，H.264 约 0.8 MB。当前全部媒体约 40 MB，上线前应放 CDN。

## 五、人物生成 v2：4K 参考 + 评分关键帧 + 首尾帧锁定循环

### 为什么重做（2026-09-25 评审）

v1 的 15 条人物视频平均像度 2.9/5（mahiro 2.5 最差：眼睛偏小、没有卧蚕、脸偏长；nana 下巴成 V 形、笑容像冷笑；alice 丢了酒红发色；unpai 发色应是暖橙棕、表情应更活泼；eimi 显老，9:16 版露肩吊带、背景是纽约帝国大厦）。根因：参考图是设定图上约 300 px 的小裁图；提示词要求「不修图、可见毛孔、暗光」；循环用 1 秒交叉淡化，笑容融化、双眼重影；慢眨眼（约 0.8 秒）显得困。

### 流程

```
经纪公司 4K 采访素材 ──▶ media:refs 抽帧（正面/3/4/侧面，Vision 选质量最高的）──▶ assets/agency/refs/<艺人>/（本地私有）
        │                                                    │
        │                                                    └─▶ media:talent refs：正面、笑脸、左右 3/4、侧面入她的 AIGC 资产组
        ▼
gpt-image-2 关键帧（每条 4 张：hero 16:9、hero 9:16、早 9:16、午 9:16；身份参考 3 张 + 同时段场景海报）
        │  每张候选由评分器打分（judge.ts：五人匿名列队 1–5 + 五官差异 + 发色）；低于 4 分自动带着差异说明重出一轮
        ▼
media:talent keyframes（默认取评分最高的候选）──▶ 资产 ID
        ▼
Seedance 2.5：同一关键帧做首帧 + 尾帧（ratio 自适应），结构化提示词 ──▶ Draft 480p ──▶ 同种子 1080p ──▶ 后期（接缝 ≤ 0.3 秒）
```

```bash
npm run media:refs -- --only mahiro                   # 从 4K 素材抽参考帧（卡面流程提供，同一工具）
npm run media:talent -- refs all                      # 参考帧入库，替换 v1 设定图裁图
npm run media:keyframes -- --only mahiro --n 2 --rounds 2   # 候选 + 评分，记录在 tools/media/out/keyframes/v2/<镜头>.json
npm run media:talent -- keyframes mahiro              # 评分最高的候选入库（可用 --pick hero-16x9=c 覆盖）
npm run media:gen -- --only mahiro-hero-16x9 --draft  # 480p 预览
npm run media:gen -- --only mahiro-hero-16x9          # 1080p 成片（沿用预览的种子；输出侧「版权」拒绝自动换种子重试，最多 3 次）
npm run media:process -- --only mahiro-hero-16x9
```

**录入虚拟角色库的依据**：已和 BytePlus 官方确认，签约艺人经授权后可以这样录入（2026-09-24）；艺人合同中含 AI 生成授权（见关键产品决策）。资产上传保持默认内容审核。上传需要一个临时公网链接（CreateAsset 只收 http(s) URL，不收 base64；本地图片直接交给 Seedance 会被拒：`may contain real person`）。两种方式：

- 默认：`tunnel.ts` 起一个 cloudflared 临时隧道，上传完即关。
- 本机代理挡住 cloudflared 时（2026-09-25 实测：DNS 不解析 `_v2-origintunneld` SRV，7844 端口 TLS 被断）：`relay.ts` 走 R2 中转。私有桶 `jstar-relay-tmp`（关闭 r2.dev，无自定义域名）+ 只读 Worker `jstar-relay`（`GET /<64 位随机令牌>/<随机名>`，其余一律 404，无列目录、无写入），令牌只存在本地。设置 `JSTAR_RELAY_URL`、`JSTAR_RELAY_TOKEN_FILE` 后 `media:talent` 自动改用中转；每个文件在资产处理完成（Active）后立即删除。整批视频完成后删除 Worker、桶和本地令牌（2026-09-25 #24：44 个文件经中转入库，完成后 Worker `jstar-relay`、桶 `jstar-relay-tmp` 与本地令牌均已删除；下次需要时按上述方式重建）。

### 关键帧怎样做到「像」

- 身份参考换成 4K 视频里抽出的 724 px 头部帧：最佳正面、另一时刻的笑脸正面、最佳 3/4 侧面。参考里的头饰、蝴蝶结、项圈是演出服装，提示词明确不许照抄。
- 每位艺人在 `manifest.ts` 里有固定的发色发型（`hair`）、饰品（`accessories`）、易跑偏的五官（`features`，如 mahiro 的大圆眼和卧蚕、nana 的圆下巴）和表情（`expression`，一律闭嘴微笑；unpai 更活泼）。四条视频同一套衣服与饰品。
- 光：正面明亮柔光、眼神光；写真集程度的自然修饰。
- 构图：16:9 人在右三分之一、胸像、脸约占画面高度三分之一、头顶离上边约 12%；9:16 胸像在上半。
- eimi：衣服改为长袖高领玫瑰色缎面衬衫配藏青丝巾（不露肩）；夜景明确为东京（东京塔），`eimi-night-9x16` 场景已重拍（原片是纽约帝国大厦）。
- 评分器在 v1 海报上的平均分与人工评审一致（都是 2.9），可作为自动门槛。

### 为什么用首尾帧锁定

Seedance 2.5 规定：带尾帧时不能再带参考图（`last frame image content cannot be mixed with reference image`），带首帧时画幅跟随首帧（`ratio` 必须为 `adaptive`）。所以人物循环只发一张关键帧（首帧 = 尾帧）：8 秒两端都锚在同一张脸上，不需要交叉淡化。时间轴：0–8 秒始终看着镜头、眼睛睁开、保持首帧的闭嘴微笑并轻轻呼吸；约 2 秒处眨一次眼；3–6 秒轻微歪头、发丝微动；6–8 秒回到首帧的姿势与表情。

**眨眼**（2026-09-25 实测）：提示词里任何情绪动作（「见到你很开心」「笑意加深」「眼睛也在笑」）都会被 Seedance 演成闭眼陶醉的笑，闭眼 0.5–2 秒，正是 v1「显困」的原因；只写「一直看着镜头」后降到约 0.5 秒，但仍比目标（0.2–0.3 秒）慢。所以 `media:process` 对人物循环先用 Vision 逐帧测眼睛开合，把每次超过 0.34 秒的眨眼只在它自己的时间窗里加速到 0.25 秒（最多 3 倍），其余帧、包括锁定的首尾帧都不动；`npm run media:check -- --only <id>` 可单独测眨眼时长和接缝。无人场景同理：`unpai-day-9x16`（晾衣绳上的围巾、飘动的云，找不到能接上的两帧）改为用自己的海报做首尾帧重拍。


- **参考图**：每人约 20 张头部特写（正面、3/4、侧面；表情不同、间隔 ≥1.5 秒），脸宽 210–440 px（4K 原片里脸本身只有这么大，比之前从设定图裁的 300 px 图清楚得多）。只裁头发和脸，不含身体。
- **像度裁判**（`tools/media/src/judge.ts`）：五人匿名列队（A–E，每人两张脸部特写，顺序每次打乱），让视觉模型给候选图对每个人打 1–5 分；她本人的分就是像度，若别人分数更高则封顶 2.5、并列封顶 3.5；≥ 4 才算达标。先后试过本地 Apple Vision 特征（认对人的比例与瞎猜相当）和"是不是同一个人"单问（三分之一把别人判成 5 分），都不可用。
- **生成**：每张卡 2 张候选，达标的最高分再用另一种打乱顺序复核一次，两次平均 ≥ 4 才发布；不达标最多再生成 2 轮，并把裁判指出的五官差异写回提示词；仍不达标就不发布，在审核表里标红。
- **尺度**：提示词强制完整着装（上衣配裤子或及膝裙，或整条连衣裙），不露大腿、不露胸，不出现艺人姓名。

## 十、人物·存在感镜头（#24 第三阶段，2026-09-26）

恋与深空官网的「3D 感」来自预渲染的电影镜头（镜头在空间里推进、角色登场 CG），不是 WebGL。这里用同样的思路，给首页每位艺人做 8 条短片，全部**接在负责人已确认的 v1 hero 循环上**（#46 已把首页恢复到 9/25 上午的 v1）。

- **锚点**：`npm run media:keyframes -- --extract-v1` 取线上 v1 hero mp4（最大的 H.264，1920×1080 / 1080×1920）的第 0 帧，存为 `<艺人>-hero-<比例>-v1` 关键帧并入资产库。站点从这些短片切回 hero 循环时，画面就停在循环开头的那一帧。
- **入场**（`-enter-`，5 秒）：先用 gpt-image-2 做一张「同一时刻、退远拍」的远景首帧：参考只用 v1 帧本身和从它裁出的脸（不写 v2 的衣服、发型、光线文字，免得和 v1 打架），画面边缘加一个虚化前景（窗帘、植物、窗框）做纵深。Seedance：first_frame = 远景，last_frame = v1 锚点，提示词只写一次平稳的推镜和轻微视差。
- **反应**（`-react-a/b/c-`，4 秒）：first_frame = last_frame = v1 锚点。a：害羞地把视线和头稍微转向一旁（与眼睛等高，不要往下看，往下看会被读成闭眼）再看回镜头；b：抬手在脸旁轻轻挥一下；c：稍微前倾、轻轻笑一下再靠回去。嘴可以微张，但不说话。
- **像度**：用 `continuity.ts` 判断，方法同 #29 的匿名列队，但参考换成五人的 v1 hero 帧（不是 4K 参考），因为要的是和已确认片子的连贯。校准：v1 片中第 4 秒的帧判给本人全是 5 分、判给别人全是 1 分。
- **接缝**：`npm run media:check -- --only <id>` 把短片首帧、尾帧和锚点关键帧各缩到 64×64 灰度做平均绝对差（0–255，阈值 12）。
- **眨眼**：和循环一样由 `media:process` 加速到约 0.25 秒；超过 1 秒的「闭眼」是往下看或笑眯眼，不是眨眼，不处理。
- 预览：只用第一位艺人（mahiro）的 8 条做 480p 预览验证提示词，其余直接 1080p。

## 十一、高清 hero 循环（#24 第四阶段，2026-09-27，负责人选方案 A）

负责人反馈线上 v1 hero（9/25 确认、#46 恢复）发虚：发布的 AV1 1080p 只有约 0.5 Mbps，H.264 约 1.3 Mbps，而 v1 的原始母带已被 v2 的生成覆盖（`tools/media/out/raw/<艺人>-hero-*.mp4` 现在是 v2 的脸）。方案 A：以 v1 画面为锚重新生成，并提高编码质量；**不覆盖任何素材**。

- **备份**：`tools/media/out/backup-2026-09-27/`（raw、retimed、state.json，本地）。
- **新 ID**：`<艺人>-herohd-16x9` / `-9x16`，8 秒，首帧 = 尾帧 = v1 hero 首帧（第十节的 `<艺人>-hero-<比例>-v1` 锚点资产），不交叉淡化（`xfade: 0`）。提示词：一直看着镜头、自然呼吸与细微表情；镜头极慢地靠近再回到原位；灯光「活」起来（城市光斑闪烁、灯光轻微跳动、一道柔光掠过、发丝和布料被微风吹动）。旧的 `<艺人>-hero-*` 目录与索引条目一字未动。

- **高质量编码**（`Shot.encode: 'hq'`，写入新的 `-hq` 文件名，旁边的旧文件保留）：AV1 CRF 20（SVT-AV1 `tune=0` 视觉质量）、H.264 CRF 17、720p H.264 CRF 20、海报 q 90（含 16:9 的 1920 宽）。实测这些低运动片子在 AV1 CRF 23 只有 1.4 Mbps、CRF 18 也只有 1.9 Mbps，所以以 CRF 定质量，不追码率数字。结果：hero AV1 0.4–0.7 → 1.1–1.8 Mbps，H.264 0.8–1.6 → 3.3–5.3 Mbps；40 条存在感片子同样重编码为 `-hq`，索引改指向 `-hq` 文件。

### 学到的（已写进工具）

1. **两张分别生成的静帧不能直接当首尾帧。** 第一版「起身离开」用坐姿关键帧做首帧、单独生成的空房间做尾帧。两张图都是 gpt-image 画的同一个房间，但机位差一点，Seedance 在 5.08 秒处直接硬切过去（缩略图单帧跳变 21.5）。草稿就已经有这个问题，当时的 `media:check` 没查出来。现在的做法：她离开的片段不设尾帧（`frames.end: 'empty'`），后面的片段从它**实际渲染出的最后一帧**开始（`{ after: 'eimi-leave-9x16' }`）。草稿接草稿，成片接成片，所以每一对的接缝都是同一帧。第一版三条的花费算在试点里，原片留在 `tools/media/out/raw/v1/`。
2. **`media:check` 新增硬切检测**：单帧跳变 ≥ 15，且是前后两帧内最大跳变的 2.5 倍以上，就判为硬切。快速的手部动作是连续的大跳变（まひろ 13.6 旁边是 12.4），不会误报。
3. **低头、看向别处都会被 Seedance 演成闭眼。** 提示词里的视线一律写「看镜头」；起身时的低头（0.54 秒）交给 `media:process --retime-only` 加速；重新编码后刚过门槛的眨眼（0.29 → 0.38 秒）会再加速一遍。
4. 远景、转身、离场时脸会变小或转开：眼睛只在脸宽 ≥ 56 px（长边 1280）且偏转 ≤ 30° 的帧上测量；只要求「首尾帧是她的那一端」有脸，离场片段反过来要求最后一帧没有人。
5. 同一个 seed 的 480p 草稿和 1080p 成片动作基本一致，但不完全相同（まひろ成片的出拳比草稿更靠近镜头），成片也要单独检查。

### 怎么做的

1. **生成**：`tools/audio/lyria.py pro|clip <输出> <提示词文件>`，经 OpenRouter 调用 Lyria 3（`config/models.json` 的 `music.*`）。请求要 `modalities: ["text","audio"]` 且必须 `stream: true`，音频在 SSE 的 `delta.audio.data`（base64）里分块返回；不管 `audio.format` 写什么，返回的都是 44.1 kHz 立体声 192 kbps MP3，文件头带 C2PA 内容凭证（AI 生成标记）。Pro 一首 $0.08（约 1.5–3 分钟），Clip 一段 $0.04（30 秒）。
2. **比稿**：每首做了 2 个 Pro 版本（默认种子 + seed 7），3 段 BGM 和うんぱい的歌另各做 1 个 Clip 版本，雨 / 雪也各让 Clip 试了一段。按 `tools/audio/check.py stats` 和 `loops.py find` 的数字挑，不靠耳朵：
   - アリス：两版都有自然结尾；选 1 号，它中段没有掉到 −30 dB 以下的空洞（2 号最静的一秒 −30.6 dB），高频延伸更好（8.4 vs 7.5 kHz）。
   - うんぱい：1 号在 20 → 125 秒之间能剪出 105 秒的循环（交叉淡化匹配 0.90），2 号最长只能剪出 50 秒的高匹配循环；Clip 版只有 30 秒，循环 18 秒太短会一直重复。
   - 温暖傍晚：2 号能剪出 79 秒、匹配 0.967 的循环（1 号 60 秒、0.942）。夜晚：1 号 80 秒、0.949，2 号中间有掉到 −33 dB 的空洞、匹配只有 0.74。俏皮：1 号 52 秒（110 BPM 正好 24 小节）、0.857；2 号 0.76。
   - 雨 / 雪：Lyria 给的是低沉的有调性氛围（频谱重心 130 Hz 左右、平坦度 0.001），不像雨；程序合成的雨重心 1.4 kHz、宽带。所以环境音用 `tools/audio/ambience.py` 合成：整段在一个固定长度上按圆周构造（整段做频域滤波的噪声、周期能整除循环长度的起伏、按取模放置的雨滴），所以天然无缝。雨 = 屋顶的低频冲刷 + 高频嘶嘶声 + 数千个玻璃上的小雨点 + 偶尔的大水滴；雪夜 = 闷住的风（会起伏）+ 窗框偶尔的哨声 + 暖炉的轻微噼啪。左右声道相关约 0.4。
3. **剪循环**：`tools/audio/loops.py make`。从选定的起点开始，在给定长度范围里找「接下来 6 秒最像起点那 6 秒」的终点（24 个对数频带能量 + 起音通量，逐帧 z 分数相关），再用波形相关精确到样点；循环体的开头 2 秒用终点之后的原音频做等功率交叉淡化，这样循环尾 → 循环头就是原曲里连续的两个样点。文件前后各再附上 0.25 秒循环自身的尾和头，播放器只循环 `[0.25, 0.25 + 长度]` 这一段：即使哪个浏览器的解码器没去掉 AAC 的前置填充，也只是循环窗口整体挪几毫秒，接缝照样无缝。
4. **响度与编码**：`tools/audio/encode.sh`，一次线性增益到目标（不用动态响度归一，那会让循环首尾的音量不一样），AAC-LC（AudioToolbox）MP4，去掉元数据。目标：她的语音是 −16 LUFS，所以作为「这一刻本身」的曲子（钢琴、耳机里的歌）也是 −16；垫在台词下面的 BGM −18，播放时再乘 0.75、她说话时降到 0.22；环境音 −26。真峰值都在 −2 dBTP 以下。
5. **听检（程序化）**：`tools/audio/check.py seam <文件>:<循环样点数>` 把 m4a 解码后取出浏览器实际循环的那一段，比较接缝处和文件里其它所有相邻位置：接缝前后 50 ms 的能量跳变、跨接缝的频谱通量都要落在本文件自己的分布里（< 95 分位），接缝样点跳变要小于本文件相邻样点差的 99 分位。上表 6 个循环全部通过。

### 原创与授权

- 所有提示词都写明「原创、不引用或模仿任何现有歌曲、作曲家、艺人」，提示词里没有任何真实艺人名或曲名；完整提示词和每个版本的去留在 `tools/audio/prompts.json`。
