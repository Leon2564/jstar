# JSTAR 关键产品决策

2026-09-24 · Lionel ｜ 修订：2026-09-26（v1.1 决定、待确认清单，#53）

## 产品形态

以 5 位已签约日本艺人为 IP 的「虚拟卡牌收集 + AI 陪伴」独立产品，与已在售的 JSTAR 实体卡通过序列码单向联动。

- **独立产品**，与 Ifanzy 完全分开：独立品牌、独立域名、独立主体。
- **纯虚拟卡**是线上主体，实体卡是另一个入口，不是主产品。
- **核心循环**：聊天 → 亲密度 → 抽卡机会 → 卡解锁语音、剧情、回忆卡 → 回到聊天。
- **Web 优先**，v1.0 与 v1.1 都不做原生 App：扫码用户不必下载，没有商店审核等待，也避开同类产品被反复下架的风险。
- **官网即产品**：未登录看到官网形态，登录后打开网站直接落在「她的陪伴首页」。

## IP 与内容尺度

IP 就是已签约的 5 位：唯井まひろ、八木奈々、うんぱい、七瀬アリス、深田えいみ。不加原创 AI 角色。

| 决策 | 内容 |
| --- | --- |
| 尺度 | 性感不露骨（写真级），全站年龄确认，注册时再确认生年月日 |
| 授权范围 | 全部内容已授权 AI 生成，无需逐张送审 |
| 内容标注 | 卡面与素材分「本人实拍」与「AI 生成」两种标注，实拍放最高稀有度 |
| 构图规则 | 一律看镜头、第一人称视角；藏青底加玫瑰粉光；保留皮肤纹理不磨皮 |
| 生成方式 | 以实拍为参考图做延伸，视频只做呼吸、眨眼、发丝等小动作 |
| 内部审核 | 保留一道轻量品牌安全抽查，不走经纪公司流程，只为避免出现让本人不舒服的内容 |
| 头部风险 | 深田えいみ体量远超其他四位，产品结构不能押在她一个人身上 |

内容供给靠四个来源：一张素材做成多层卡（静图、动图、语音、剧情）、由对话生成的专属回忆卡、跟随本人现实动态的限定卡、艺人本人低成本参与的语音与自拍。

## 经济与合规规则

四条硬规则，已经写进代码，改动需要先过法务。

1. **随机只发生在一侧。** 线下实体盲盒的随机性在拆包时发生；线上付费抽卡的产出只能是数字卡，绝不抽中后寄送实物。线上付费抽实物就是「オンラインオリパ」，2026 年 9 月已有律所就此向消费者庁申请调查。
2. **数字卡不可变现、不可交易。** 一旦允许换回现金或可流通代币，产品就回到博彩边界。
3. **不做集齐换奖。** 付费抽卡集齐一套换奖品在《景品表示法》下被禁止（カード合わせ）。集齐只给图鉴荣誉，奖励只从免费或确定性购买渠道发放。现有实体卡文案里的「集齐可能有特典」需要撤下或送审。
4. **概率公示，抽卡可复现。** 概率在界面公示，修改需公告；每次抽卡保存随机种子与结果，纠纷可回放。

**收入结构**：抽卡是利润引擎（卡面一次生产、无限次售卖），订阅负责留存，实体盲盒赚零售毛利并承担获客。聊天是成本项，所以自托管模型是结构性优势——Talkie 与星野的 C 端毛利只有 4.7%，原因就是聊天的持续推理成本。

**序列码从「抽选」改为「保底 + 抽选」**：每个码保底解锁对应数字卡加一段短期体验，抽选只留给稀缺奖品。原来的纯抽选让大多数买卡用户扫码后一无所得，等于挡住了最精准的一批人。

## 产品结构与主流程

**两个站分工**：JSTAR 站只卖实体卡并承担跳转；陪伴站是产品本体，所有体验在这里完成。两站之间唯一的连接是序列码。下一批印刷时，卡上 QR 直接编码成「陪伴站兑换页 + 该卡序列码」，扫码自动填入。

**一个站两种状态**：访客看到官网形态（首页、STARS、玩法、卡牌图鉴、活动、充值、序列码兑换）；登录后直接落在她的首页，官网形态退到二级入口。手机端登录后用底部导航，桌面端改为顶部导航。

流程：

- 线下：扫实体卡 QR → 年龄确认 → 序列码自动填入 → 翻卡入册、她打招呼 → 注册保存 → 陪伴首页
- 线上：官网首页 → 选择她 → 免注册试聊 3 条 → 注册保存 → 陪伴首页
- 汇合后：聊天 · 抽卡 · 卡册

**已定的细节**：扫码到听见她说话不超过 3 步，先让她打招呼、先看到卡，最后才要求注册；访客免登录可试聊 3 条；注册用邮箱验证码（不靠 Google，社媒内置浏览器里常失效；LINE 登录于 2026-09-27 移除，v1.0 只用邮箱）；角色切换是「选一位主推 + 顶部头像随时切换」，不用恋与深空那种随机出现。

**v1.0 页面**共 21 屏：年龄确认、加载、首页、菜单、JSTARS、玩法、卡牌图鉴、活动、选人、试聊、注册、序列码输入、翻卡结果、陪伴首页、聊天、抽卡、抽卡结果、卡册、卡片详情、充值、我的。

- **v1.0 不做、v1.1 做**（见下节「2026-09-26 v1.1 决定」）：约会与相处（她房间里的场景、约定）、换装（变体卡）、小游戏（场景里的猜拳、大喜利等）、语音输入。
- **v1.0 与 v1.1 都不做**：剧情主线、家园、手机模拟、桌面小组件。

## 工程决策

工程已交付为 monorepo（`jstarcardsai`），四端加一个共用包。

| 端 | 职责 | 绝不负责 |
| --- | --- | --- |
| `apps/web` | 展示、交互、四语言、离线原型模式 | 判定积分、抽卡结果、试聊次数 |
| `apps/api` | 身份、钱包、序列码、抽卡、审计、管理接口 | 生成人设回复、判断内容尺度 |
| `apps/admin` | 卡牌与素材、Pickup 排期、序列码批次与作废、客服与补填、审核、审计、指標 | 直接读写数据库 |
| `apps/agent` | 人设提示词、记忆、内容边界、模型路由 | 认识用户是谁、扣款 |

拆出 agent 服务的原因：**内容边界要能被单独审计和单独改**。经纪公司或律师要看尺度规则时，只看人设配置和边界文件，不需要读业务代码。

**服务端权威**：积分、抽卡结果、试聊次数、序列码是否用过，全部后端判定，浏览器只做展示缓存并在加载时逐字段校验。

**内容边界四类处理**：未成年与索要现实住址等硬拦截；露骨请求由人设用自己的语气婉拒（系统式拒绝会破坏关系）；被问是不是真人必须说明自己是 AI；自伤话题转支持话术。模型输出再过一遍出站过滤。

**多语言**：日文、繁体中文、英文、韩文。首次访问按浏览器语言识别，可随时切换并持久化；只下载当前语言词条与对应字体；英文与韩文显示罗马字姓名，日文与繁中显示原名并启用竖排。

**质量基线**（2026-09-24 实测）：单测 83 项与端到端 55 项通过；axe 无障碍严重问题 0；6 种视口 × 2 语言无横向滚动；最大内容绘制 2.40 秒、最慢点击响应 88 毫秒、首包 68.6 KB（gzip）。

## 市场与上线顺序

**日本与繁中圈（台湾、香港、海外华人）同时首发**，美国往后放，中国大陆不碰。

理由：艺人在日本，日本付费抽卡意愿最强、实体卡文化最成熟；这批艺人在繁中圈有现成认知，ジューシーハニー在台湾已形成热度；デジコレッタ 已经在做日文、繁中、英文三语，说明这个市场组合有人验证过。

**渠道**：线下从艺人粉丝活动、见面会切入，签名卡是天然周边；线上复用已有的 KOC 与矩阵号能力。

**风险**：真人 IP 的收入上限约等于粉丝数 × 付费率 × 单价，没有平台流量放大。玩法可以照抄，粉丝抄不来。

## 过程中被推翻的判断

| 原判断 | 现结论 | 推翻原因 |
| --- | --- | --- |
| 独立品牌只做全年龄、走 App Store | Web 优先，支付与年龄验证按成人向处理 | IP 是成人影片演员，粉丝是成年男性；但デジコレッタ 证明写真级尺度能以 16+ 上架，商店版本仍是可选项 |
| 品牌与基础设施都与 Ifanzy 切开 | 品牌独立，支付与 KYC 基础设施复用 | 同一批高风险通道能力没必要重建 |
| 市场顺序：日本 → 美国 | 日本 + 繁中圈 → 美国 | 这批艺人在繁中圈的认知度远高于欧美 |
| 参照多个产品各取所长 | 只留 Talkie 一个主参照 | 拼的产品越多，背后假设越容易互相打架 |
| 角色少是最大瓶颈 | 瓶颈是单角色的月度卡面产能 | 恋与深空只有 5 位男主，两年流水约 9.34 亿美元 |
| 实拍档期是供给上限 | 授权已覆盖 AI 生成，瓶颈转为「像不像、尺度稳不稳、还值不值钱」 | 全部内容已授权 |
